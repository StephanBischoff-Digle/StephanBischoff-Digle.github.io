## Introduction

This is the first part of the [Advent of Code (Day 1)](https://adventofcode.com/2025/day/1) problem solving series.
Day 1 is traditionally a warm-up puzzle.
The following days will increase the difficulty gradually.

### Input Format and Semantics

The input format is shared for this day.
It has the following grammar:
![input grammar](/img/aoc/25-01-ebnf.svg)

So, we get a list of instructions.
Each instruction starts with either `'L'` or `'R'`, followed by a non-negative integer.
The whole instruction is basically a signed offset with `'L'` denoting the negative direction.

We have to apply the instructions on a dial of size 100 (0 to 99), which initially points at the 50 position.
The instruction is applied by modular-addition, adding it to the dial state.
It's important to note that the value of the instruction may be larger than the dial space.

![instruction image](/img/aoc/25-01-clock.svg)

### Line Parsing

The parsing of the line is rather trivial:

1. decide the sign based on the first character,
2. parse the rest of the line into an integer and
3. return the parsed integer with the sign applied

```c++,name=line parsing
namespace advent {
std::optional<int32_t> parse_line(std::string_view line) {
    // Decide on sign
    const bool POSITIVE = (line[0] == 'R');
    line.remove_prefix(1);

    // Parse the integer
    int32_t amount{};
    auto [_, ec] = std::from_chars(
        line.data(),                    // start
        line.data() + line.size(),      // end
        amount                          // target
    );

    // Parsing went well
    if (ec == std::errc()) {
        return  POSITIVE ? amount : -amount;
    }

    // Error cases
    return std::nullopt;
}
}  namespace advent
```

## Part 1

In the first part we have to count how often we reach the dials 0 position.
So the processing is rather trivially applying the instruction, mapping it back into the dial space and checking, whether the dial is at the position 0.
Output the count of 0 positions as the problem solution.

```c++,name=Part 1
// ... open and read input file as infile

int32_t  dial    = 50;
uint32_t counter = 0;

std::string line;
while (std::getline(infile, line)) {
    // parse the line, abort if we failed to parse
    auto parsed = advent::parse_line(std::string_view{line});
    if (!parsed) {
        std::cout << "Failed to parse, aborting\n";
        return 1;
    }

    // calculate the new dial position and check, if we reached 0
    dial = (dial + *parsed) % 100;
    if (dial == 0) {
        counter++;
    }
}
std::cout << counter << '\n';
```

## Part 2

In the second part, we have to count every time the dial sees the 0 position.
Not only when the dial stops there, but everytime the dial passes the position as well.

To achieve this, we now require a correct implementation of the modulus operation.
The default C++ `%` preserves the sign, such that `-25 % 100 = -25` instead of the expected `75`.
The following implementation will be used.
- It first calculates the default modulus: `x % base`
- The result might be negative, so we bring it back to the domain by adding the base onto the result `x % base + base`
- Finally, in the non-negative case, we are now way beyond our domain, so we bring it back to our domain by applying the `%` again: `(x % base + base) % base`

```c++,name=Correct Modulus
namespace advent {

/// Computes the correct modulo
/// Does not check for overflow or a 0 base!
template<typename T>
T mod(T x, T base) {
    return (x % base + base) % base;
}
}  // namespace advent
```

I mentioned in the introduction, that our instructions can be bigger than the dial space.
We can integer-divide by the size of the dial space (100) to find the number of guaranteed 0 passes.
So for an instruction 250, we are guaranteed to pass the 0 at least two times.
We add that to the counter.

Now, we only have to deal with the remaining parts of the instruction (50, in case of the 250 example).
Lets add that to the dial and check, if we passed the 0 again, by comparing, if the dial value differs between the addition of the instruction and applying the `advent::mod` operation.
If it differs, we add one to the counter.

Lastly, there is an edge case when the dial is at position 0 and the next instruction is negative.
Without correction, `0 + (-5) = -5` and `mod(-5, 100) = 95` would differ, incorrectly suggesting we crossed 0.
But we actually moved away from it.
Adding 100 to the dial first (`100 + (-5) = 95`) ensures that the comparison that determines the 0 crossing is correct.
In any other case, we pass the 0 position and should count accordingly.

```c++,name=Part 2
// ... open and read input file as infile
int32_t       dial    = 50;
uint32_t      counter = 0;

std::string line;
while (std::getline(infile, line)) {
    auto parsed = advent::parse_line(std::string_view{ line });
    if (!parsed) {
        std::cout << "Abort processing\n";
        return 1;
    }
    
    // If the dial lands on 0 and the next input is a negative number,
    // we don't want to count passing 0.
    if (dial == 0 && *parsed < 0) {
        dial += 100;
    }

    // The input may be more than one dial revolution.
    if (std::abs(*parsed) >= 100) {
        counter += static_cast<uint32_t>(std::abs(*parsed) / 100);
        *parsed = *parsed % 100;
    }

    // Check if we passed or landed on 0:
    // - tmp_dial != dial means that we wrapped around (crossed 0)
    // - tmp_dial == 0 menas we landed on the 0
    dial += *parsed;
    auto tmp_dial = advent::mod(dial, 100);
    if (tmp_dial != dial || tmp_dial == 0) {
        counter++;
        dial = tmp_dial;
    }
}

std::cout << counter << '\n';
```
